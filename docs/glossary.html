MAC (Mandatory Access Control)
주체와 객체에 사전에 부여된 보안등급(Security Label)을 비교하여 접근 허용 여부를 결정하며, 사용자가 임의로 접근 권한을 변경할 수 없고 시스템(보안관리자)이 중앙에서 접근 규칙을 강제하는 접근통제 모델의 명칭을 영문 약어로 쓰시오.

MAC(강제적 접근통제)는 주체(사용자)와 객체(자원)에 각각 보안등급(비밀, 대외비 등)을 부여하고, 이 레이블을 비교하여 접근을 허용하거나 거부하는 방식이다. 자원 소유자가 임의로 권한을 변경할 수 없고 시스템 관리자가 정한 정책에 따라 강제적으로 통제되는 것이 특징이며, 군사/정부 시스템처럼 보안등급이 명확한 환경에서 주로 사용된다. 이는 자원 소유자가 접근 권한을 자유롭게 부여할 수 있는 DAC(임의적 접근통제)와 대비되며, 사용자의 역할(Role)에 따라 권한을 부여하는 RBAC와도 구분된다. 대표적으로 벨-라파둘라(Bell-LaPadula) 모델이 기밀성을 보장하는 MAC의 한 예로 자주 출제된다.

📎 함께 암기하기
  • DAC: 자원 소유자가 접근권한을 임의로 부여하는 임의적 접근통제
  • RBAC: 사용자의 역할(Role)에 따라 권한을 부여하는 역할기반 접근통제
  • Bell-LaPadula 모델: 기밀성 유지를 위한 MAC 기반 모델로 No Read Up, No Write Down 원칙 적용
  • Biba 모델: 무결성 유지를 위한 모델로 No Write Up, No Read Down 원칙 적용
  • OTP: 매번 다른 일회용 비밀번호를 생성해 인증하는 기술

MITM(Man-In-The-Middle) 공격
공격자가 네트워크 패킷을 가로채어 송신자와 수신자 사이에서 몰래 통신 내용을 중계하며 도청하거나 변조하는 공격 기법을 영문 약어로 쓰시오.

MITM 공격은 통신하는 두 당사자 사이에 공격자가 끼어들어 패킷을 가로채고 도청 또는 변조하는 공격이다. ARP 스푸핑 등의 기법이 이를 수행하는 대표적인 방법으로 사용된다.

TCP
OSI 7계층 중 전송 계층(4계층)에서 동작하며, 연결 지향적이고 신뢰성 있는 데이터 전송을 보장하는 프로토콜은 무엇인가?

TCP(Transmission Control Protocol)는 3-way handshake를 통해 연결을 설정하고, 순서 제어와 오류 검출 및 재전송을 통해 신뢰성 있는 데이터 전송을 보장한다. 이는 비연결형이며 신뢰성을 보장하지 않는 UDP와 대비된다.

출제일: 2026-09-29
라우팅 프로토콜(Routing Protocol)
네트워크 계층에서 동작하며, IP 주소를 기반으로 송신 호스트가 목적지까지의 최적 경로를 설정하는 데 사용되는 프로토콜을 통칭하는 용어를 쓰시오. (예: RIP, OSPF 등이 속하는 상위 개념)

라우팅 프로토콜은 네트워크 계층(OSI 3계층)에서 라우터 간 경로 정보를 교환하여 최적의 패킷 전달 경로를 결정하는 데 사용되는 프로토콜의 총칭이다. RIP, OSPF, BGP 등이 대표적인 예이다.

세션 하이재킹(Session Hijacking)3번 출제
공격자가 정상 사용자와 서버 간에 이미 성립된 세션의 식별자(세션 ID)를 가로채거나 추측하여, 인증 절차 없이 해당 세션을 탈취해 정상 사용자인 것처럼 행세하는 공격 기법을 쓰시오.

세션 하이재킹은 TCP 연결이나 웹 세션에서 사용되는 세션 ID(또는 시퀀스 번호)를 공격자가 스니핑, 예측, 또는 XSS 등을 통해 탈취한 뒤 해당 세션의 권한을 그대로 이어받아 서버에 접근하는 공격이다. 대표적으로 TCP 세션 하이재킹은 시퀀스 번호를 추측해 정상 통신 중간에 끼어드는 방식이며, 웹 환경에서는 쿠키에 저장된 세션 ID를 탈취하는 방식이 많이 쓰인다. 대응책으로는 세션 ID를 추측하기 어렵게 난수화하고, HTTPS로 통신을 암호화하며, 일정 시간 후 세션을 만료시키는 타임아웃을 적용하는 것이 있다. 이는 사용자의 자격증명 자체를 훔치는 피싱과 달리 이미 인증된 세션을 가로챈다는 점에서 구분되며, 패킷을 엿듣는 스니핑과는 달리 단순히 보는 것이 아니라 세션을 능동적으로 탈취해 사용한다는 차이가 있다.

  • 스니핑(Sniffing): 네트워크 패킷을 몰래 엿보는 수동적 공격
  • 스푸핑(Spoofing): IP나 MAC 주소 등을 속여 신분을 위장하는 공격
  • ARP 스푸핑: ARP 캐시를 조작해 중간자 공격을 수행하는 기법
  • 피싱(Phishing): 가짜 사이트나 메일로 사용자 인증정보를 속여 탈취
  • XSS(Cross Site Scripting): 악성 스크립트를 삽입해 쿠키나 세션 정보를 탈취하는 공격

스푸핑 (Spoofing)
공격자가 정상적인 사용자인 것처럼 가장하여 네트워크 상에서 송신자의 IP 주소나 MAC 주소 등을 위조해 상대방을 속이는 공격 기법을 무엇이라 하는가?

스푸핑은 IP, ARP, DNS 등 다양한 계층에서 출발지 정보를 위조하여 정상 사용자로 위장하는 공격 기법이다. 대표적으로 IP 스푸핑, ARP 스푸핑, DNS 스푸핑 등이 있다.

시퀀스 다이어그램 (Sequence Diagram)
객체 간에 메시지를 주고받는 순서를 생명선(Lifeline)과 활성 구간(Activation Bar)을 사용해 시간 흐름에 따라 표현하는 UML 행위 다이어그램(동적 다이어그램)의 명칭을 쓰시오.

시퀀스 다이어그램은 UML의 행위(동적) 다이어그램 중 상호작용 다이어그램에 속하며, 객체들을 생명선(Lifeline)으로 세로로 배치하고 시간의 흐름에 따라 객체 간 주고받는 메시지를 화살표로 표현한다. 활성 구간(Activation Bar, Focus of Control)은 해당 객체가 실제로 처리를 수행하고 있는 시간을 나타낸다. 유사한 상호작용 다이어그램인 커뮤니케이션 다이어그램(Collaboration Diagram)은 시간 순서보다 객체 간 관계와 메시지 교환 구조를 강조한다는 점에서 차이가 있다. 시험에서는 시퀀스 다이어그램을 구조(정적) 다이어그램인 클래스 다이어그램과 혼동하지 않는 것이 중요하며, 동적 다이어그램에는 시퀀스, 상태(State), 액티비티(Activity), 유스케이스(Use Case), 커뮤니케이션, 타이밍 다이어그램이 포함된다.

📎 함께 암기하기
  • 커뮤니케이션 다이어그램: 객체 간 관계와 메시지 흐름을 구조적으로 표현하는 상호작용 다이어그램
  • 상태 다이어그램: 객체의 상태 변화를 이벤트에 따라 표현하는 행위 다이어그램
  • 액티비티 다이어그램: 업무 흐름이나 프로세스의 순서를 표현하는 행위 다이어그램
  • 클래스 다이어그램: 시스템의 정적 구조(클래스, 속성, 관계)를 표현하는 구조 다이어그램
  • 유스케이스 다이어그램: 시스템과 액터 간의 기능적 상호작용을 표현하는 행위 다이어그램

애자일(Agile)2번 출제
요구사항이 자주 변경되는 환경에 적합하며, 짧은 주기(스프린트)로 반복적인 개발과 고객 피드백을 중시하는 소프트웨어 개발 방법론을 무엇이라 하는가?

애자일 방법론은 계획보다 변화에 대한 유연한 대응을 중시하며, 짧은 반복 주기(스프린트)를 통해 고객과 지속적으로 소통하며 점진적으로 소프트웨어를 완성해 나가는 개발 방법론이다. 대표적으로 스크럼(Scrum), XP(eXtreme Programming) 등이 있다.

애자일(Agile) 방법론3번 출제
소프트웨어 개발 과정에서 요구사항 분석, 설계, 구현, 테스트 등의 전체 과정을 짧은 주기(이터레이션)로 반복하면서 점진적으로 완성도를 높여가는 개발 방법론으로, 고객과의 지속적인 협업과 변화에 대한 유연한 대응을 강조하는 방법론을 무엇이라 하는가?

애자일 방법론은 폭포수 모델과 달리 짧은 반복 주기(스프린트)를 통해 소프트웨어를 점진적으로 개발하며, 고객 피드백을 빠르게 반영하고 변화하는 요구사항에 유연하게 대응하는 것을 핵심 가치로 한다. 대표적으로 스크럼(Scrum), XP(eXtreme Programming) 등이 있다.

응집도(Cohesion)
모듈 내부의 처리 요소들이 서로 관련이 있는 정도를 나타내며, 값이 높을수록 모듈의 독립성과 재사용성이 좋아지는 소프트웨어 설계 품질 지표를 무엇이라 하는가?

응집도는 모듈 내부 구성 요소들이 하나의 목적을 위해 얼마나 밀접하게 관련되어 있는지를 나타내는 척도이다. 응집도가 높을수록 모듈의 독립성이 강해지고 유지보수가 쉬워지므로 좋은 설계로 평가된다. 결합도와 반대로 응집도는 높을수록 바람직하다.

정규화(Normalization)3번 출제
데이터베이스 설계에서 하나의 릴레이션(테이블)에 속성 간의 함수적 종속 관계를 분석하여, 데이터의 중복을 최소화하고 삽입/삭제/갱신 이상(anomaly)을 방지하기 위해 테이블을 분해해 나가는 과정을 무엇이라 하는가?

정규화는 함수적 종속성을 기반으로 테이블을 여러 개로 분해하여 데이터 중복을 줄이고 이상 현상을 방지하는 데이터베이스 설계 기법이다. 1정규형부터 BCNF, 4정규형 등 단계적으로 진행된다.

출제일: 2026-10-01, 2026-10-02, 2026-10-03
제2정규형(2NF)4번 출제
릴레이션에서 기본키가 아닌 속성이 기본키의 일부분에 종속되는 부분 함수 종속성을 제거하여 완전 함수 종속 관계로 만드는 정규화 단계를 무엇이라 하는가?

제1정규형을 만족하는 릴레이션에서 부분 함수 종속을 제거하면 제2정규형이 된다. 이는 기본키가 복합키일 때 일부 속성만으로 결정되는 종속성을 없애는 과정이다.

출제일: 2026-09-29, 2026-10-07, 2026-10-08, 2026-10-09
제3정규형(3NF)3번 출제
릴레이션에서 기본키가 아닌 모든 속성이 기본키에 대해 이행적 함수 종속을 가지지 않도록 제거하는 정규화 단계는 제 몇 정규형인가?

제3정규형은 제2정규형을 만족하면서 기본키가 아닌 속성들이 기본키에 이행적 함수 종속(A→B, B→C이면 A→C)되지 않도록 분해하는 단계이다. 이를 통해 데이터 중복과 갱신 이상을 줄일 수 있다.

참조 무결성(Referential Integrity)
관계형 데이터베이스에서 외래키(Foreign Key) 값이 참조하는 테이블의 기본키 값으로 반드시 존재하거나 NULL이어야 하며, 참조되는 튜플이 삭제되거나 변경될 때 참조하는 테이블과의 일관성을 유지하도록 보장하는 무결성 제약조건을 쓰시오.

참조 무결성은 외래키가 참조하는 다른 테이블의 기본키 값이 실제로 존재하거나 NULL이어야 한다는 제약으로, 한 테이블에서 다른 테이블을 참조할 때 두 테이블 간의 일관성을 유지하기 위한 규칙이다. 이 제약조건이 적용되면 참조되는 레코드를 삭제하거나 수정할 때 CASCADE, SET NULL, RESTRICT 같은 옵션을 통해 연쇄 동작 방식을 정할 수 있다. 개체 무결성이 기본키가 NULL이 될 수 없고 중복될 수 없다는 규칙인 것과 달리, 참조 무결성은 테이블 간의 관계(외래키)에 대한 규칙이라는 점에서 구분된다. 실기 시험에서는 흔히 개체 무결성과 참조 무결성을 혼동하여 묻는 문제가 출제되므로, 각각이 적용되는 대상(기본키 vs 외래키)을 정확히 구분해서 암기해야 한다.

📎 함께 암기하기
  • 개체 무결성: 기본키는 NULL이 될 수 없고 중복되지 않아야 함
  • 도메인 무결성: 속성 값이 정의된 도메인(데이터 타입, 범위) 내에 있어야 함
  • 키 무결성: 하나의 릴레이션에 후보키가 2개 이상 존재할 수 없다는 규칙은 아니며 유일성을 보장
  • CASCADE: 참조 무결성 위반 시 연쇄적으로 삭제/수정이 전파되는 옵션
  • 외래키(Foreign Key): 다른 테이블의 기본키를 참조하는 속성

팩토리 메서드 패턴(Factory Method Pattern)2번 출제
객체를 생성하는 과정을 캡슐화하여, 서브클래스에서 어떤 클래스의 인스턴스를 생성할지 결정하도록 하는 생성 패턴으로, 'new' 연산자 직접 호출을 피하고 객체 생성을 하위 클래스에 위임하는 디자인 패턴의 이름을 쓰시오.

팩토리 메서드 패턴은 객체 생성 로직을 서브클래스로 위임하여 클라이언트 코드가 구체적인 클래스를 알 필요 없게 만드는 생성 패턴이다. GoF 디자인 패턴 중 생성 패턴(Creational Pattern)에 속한다.
