Isolation(고립성/격리성)
데이터베이스 트랜잭션의 ACID 특성 중, 여러 트랜잭션이 동시에 실행될 때 각 트랜잭션이 다른 트랜잭션의 중간 연산 결과를 볼 수 없도록 보장하는 특성의 이름을 영문 용어로 쓰시오.

Isolation(격리성)은 여러 트랜잭션이 동시에 실행되더라도 각 트랜잭션이 마치 단독으로 실행되는 것처럼 다른 트랜잭션의 중간 수행 결과에 영향을 받지 않아야 한다는 특성이다. 이를 완벽히 보장하면 동시성이 떨어지므로 실제 DBMS는 Read Uncommitted, Read Committed, Repeatable Read, Serializable 등 여러 격리 수준(isolation level)을 제공해 성능과 일관성 사이에서 트레이드오프를 조절한다. 격리성이 낮으면 Dirty Read, Non-repeatable Read, Phantom Read 같은 이상 현상이 발생할 수 있다. 시험에서는 Atomicity(원자성), Consistency(일관성), Durability(지속성)와 혼동하지 않도록 각 특성의 정의를 명확히 구분해 암기해야 한다. 특히 Isolation은 동시성 제어(concurrency control)와 밀접하게 연결되는 개념으로 자주 함께 출제된다.

📎 함께 암기하기
  • Atomicity: 트랜잭션의 연산은 전부 실행되거나 전혀 실행되지 않아야 함
  • Consistency: 트랜잭션 수행 전후 데이터베이스가 일관된 상태를 유지해야 함
  • Durability: 커밋된 트랜잭션의 결과는 영구적으로 반영되어야 함
  • 격리 수준(Isolation Level): Read Uncommitted, Read Committed, Repeatable Read, Serializable 등 격리 강도 단계
  • Dirty Read: 다른 트랜잭션이 커밋하지 않은 데이터를 읽는 이상 현상

MAC (Mandatory Access Control)
주체와 객체에 사전에 부여된 보안등급(Security Label)을 비교하여 접근 허용 여부를 결정하며, 사용자가 임의로 접근 권한을 변경할 수 없고 시스템(보안관리자)이 중앙에서 접근 규칙을 강제하는 접근통제 모델의 명칭을 영문 약어로 쓰시오.

MAC(강제적 접근통제)는 주체(사용자)와 객체(자원)에 각각 보안등급(비밀, 대외비 등)을 부여하고, 이 레이블을 비교하여 접근을 허용하거나 거부하는 방식이다. 자원 소유자가 임의로 권한을 변경할 수 없고 시스템 관리자가 정한 정책에 따라 강제적으로 통제되는 것이 특징이며, 군사/정부 시스템처럼 보안등급이 명확한 환경에서 주로 사용된다. 이는 자원 소유자가 접근 권한을 자유롭게 부여할 수 있는 DAC(임의적 접근통제)와 대비되며, 사용자의 역할(Role)에 따라 권한을 부여하는 RBAC와도 구분된다. 대표적으로 벨-라파둘라(Bell-LaPadula) 모델이 기밀성을 보장하는 MAC의 한 예로 자주 출제된다.

📎 함께 암기하기
  • DAC: 자원 소유자가 접근권한을 임의로 부여하는 임의적 접근통제
  • RBAC: 사용자의 역할(Role)에 따라 권한을 부여하는 역할기반 접근통제
  • Bell-LaPadula 모델: 기밀성 유지를 위한 MAC 기반 모델로 No Read Up, No Write Down 원칙 적용
  • Biba 모델: 무결성 유지를 위한 모델로 No Write Up, No Read Down 원칙 적용
  • OTP: 매번 다른 일회용 비밀번호를 생성해 인증하는 기술

MAC (강제적 접근통제, Mandatory Access Control)
주체와 객체에 보안 등급(Security Label)을 부여하고, 관리자가 정한 정책에 따라 주체가 자신의 등급보다 낮은 보안 수준의 정보를 기록하지 못하도록 하며(No Write Down), 자신의 등급보다 높은 수준의 정보를 읽지 못하도록(No Read Up) 강제하는 접근통제 모델을 무엇이라 하는가? (벨-라파듈라 모델이 대표적으로 구현하는 이 접근통제 방식의 명칭을 쓰시오)

MAC은 시스템이 사전에 정의한 보안 등급과 규칙에 따라 접근 권한을 강제로 통제하는 방식으로, 주체(사용자)나 객체(자원)의 소유자가 임의로 권한을 변경할 수 없다는 점이 특징이다. 대표적으로 벨-라파듈라(Bell-LaPadula) 모델은 기밀성을 보장하기 위해 No Read Up(낮은 등급 주체가 높은 등급 객체를 읽을 수 없음)과 No Write Down(높은 등급 주체가 낮은 등급 객체에 쓸 수 없음) 규칙을 적용한다. 반대로 비바(Biba) 모델은 무결성을 보장하기 위해 반대 방향의 규칙(No Write Up, No Read Down)을 적용한다는 점에서 혼동하지 않도록 주의해야 한다. 임의적 접근통제(DAC)는 객체의 소유자가 권한을 임의로 부여할 수 있다는 점에서 MAC과 대조되며, 역할기반접근통제(RBAC)는 사용자의 역할(Role)에 따라 권한을 부여하는 방식으로 또 다른 분류에 속한다.

📎 함께 암기하기
  • DAC: 객체 소유자가 임의로 접근 권한을 설정하는 임의적 접근통제
  • RBAC: 사용자의 역할에 따라 권한을 부여하는 역할기반 접근통제
  • Bell-LaPadula 모델: 기밀성 보장을 위한 No Read Up, No Write Down 규칙의 MAC 모델
  • Biba 모델: 무결성 보장을 위한 No Write Up, No Read Down 규칙의 모델
  • OTP: 매번 다른 일회용 비밀번호를 생성해 인증하는 기술

MITM(Man-In-The-Middle) 공격
공격자가 네트워크 패킷을 가로채어 송신자와 수신자 사이에서 몰래 통신 내용을 중계하며 도청하거나 변조하는 공격 기법을 영문 약어로 쓰시오.

MITM 공격은 통신하는 두 당사자 사이에 공격자가 끼어들어 패킷을 가로채고 도청 또는 변조하는 공격이다. ARP 스푸핑 등의 기법이 이를 수행하는 대표적인 방법으로 사용된다.

NAT (Network Address Translation)
하나의 공인 IP 주소를 여러 사설 IP 주소 사용자가 공유하여 인터넷에 접속할 수 있도록, 패킷이 라우터나 방화벽을 통과할 때 송수신 IP 주소(및 포트 번호)를 변환해주는 기술을 무엇이라 하는가?

NAT는 사설 네트워크 내부의 IP 주소를 외부에서 사용 가능한 공인 IP 주소로 변환해주는 기술로, IPv4 주소 고갈 문제를 완화하고 내부 네트워크 구조를 외부에 숨겨 보안성을 높이는 효과도 있다. 포트 번호까지 함께 변환하여 여러 내부 호스트가 하나의 공인 IP를 공유하는 방식을 PAT(Port Address Translation) 또는 NAPT라고 부르며 실무에서 가장 널리 쓰인다. NAT는 변환 테이블을 유지해야 하므로 연결 추적 상태를 관리해야 하고, 이 때문에 일부 P2P나 VoIP 프로토콜에서 NAT 통과(NAT Traversal) 문제가 발생하기도 한다. CIDR, 서브네팅과 함께 묶여 출제되는 경우가 많으므로 각 개념의 목적 차이를 구분해서 기억해야 한다.

📎 함께 암기하기
  • CIDR: 클래스 없는 주소 할당 방식으로 네트워크/호스트 비트를 가변 길이로 나눔
  • 서브네팅: 하나의 네트워크를 서브넷 마스크로 분할하는 작업
  • PAT(NAPT): 포트 번호까지 변환하여 다수 내부 호스트가 하나의 공인 IP를 공유
  • 방화벽: NAT 기능을 함께 수행하며 패킷 필터링으로 내부 네트워크를 보호
  • IPv4 주소 고갈: NAT 도입의 주요 배경이 된 문제

ON DELETE CASCADE
외래키 제약조건에서 부모 테이블의 행이 삭제될 때, 이를 참조하는 자식 테이블의 관련 행들도 자동으로 함께 삭제되도록 지정하는 옵션의 이름을 영문으로 쓰시오.

ON DELETE CASCADE는 외래키 제약조건을 정의할 때 사용하는 참조 무결성(referential integrity) 옵션으로, 부모 테이블의 레코드가 삭제되면 이를 참조하는 자식 테이블의 레코드도 자동으로 연쇄 삭제되게 한다. 이는 부모 키가 삭제되었는데 자식 테이블에 참조가 남아 고아 레코드(orphan record)가 생기는 무결성 위반 상황을 방지하기 위한 방법이다. 반대로 ON DELETE SET NULL은 부모가 삭제될 때 자식의 외래키 값을 NULL로 설정하고, ON DELETE RESTRICT(또는 NO ACTION)는 자식 레코드가 존재하면 부모 삭제 자체를 거부한다. 실기에서는 CASCADE, SET NULL, RESTRICT의 동작 차이를 구분하는 문제가 자주 나오므로 각 옵션이 삭제/갱신 시 어떻게 동작하는지 명확히 암기해야 한다. 무결성 제약조건 중에서도 이는 개체 무결성이 아니라 참조 무결성에 해당하는 개념임을 주의해야 한다.

📎 함께 암기하기
  • 참조 무결성(Referential Integrity): 외래키 값은 참조하는 테이블의 기본키 값과 일치하거나 NULL이어야 함
  • 개체 무결성(Entity Integrity): 기본키는 NULL이 될 수 없고 유일해야 함
  • ON DELETE SET NULL: 부모 삭제 시 자식의 외래키를 NULL로 설정
  • ON DELETE RESTRICT: 자식 레코드가 있으면 부모 삭제를 거부
  • 도메인 무결성(Domain Integrity): 속성 값이 정의된 도메인(자료형, 범위)을 만족해야 함

OSPF (Open Shortest Path First)
자신이 속한 라우터들의 링크 상태(비용, 대역폭 등) 정보를 전체 라우터에 플러딩 방식으로 전파하고, 각 라우터가 이를 바탕으로 다익스트라(Dijkstra) 알고리즘을 이용해 최단 경로 트리를 계산하는 내부 게이트웨이 프로토콜(IGP)은 무엇인가?

OSPF는 링크 상태(Link State) 알고리즘을 사용하는 대표적인 내부 게이트웨이 프로토콜로, 각 라우터가 자신과 연결된 링크의 상태 정보를 LSA(Link State Advertisement)를 통해 네트워크 전체에 플러딩하고, 이를 모아 만든 링크 상태 데이터베이스(LSDB)를 바탕으로 다익스트라 알고리즘을 수행해 최단 경로를 계산한다. 이는 이웃 라우터에게만 자신의 라우팅 테이블 전체를 주기적으로 전달하는 거리 벡터(Distance Vector) 방식의 RIP과 대비되는 특징이다. OSPF는 에어리어(Area) 개념을 도입해 대규모 네트워크를 계층적으로 관리할 수 있고 수렴 속도가 빠르다는 장점이 있다. 실기에서는 OSPF를 RIP(거리 벡터, 홉 카운트 기반)이나 BGP(자율 시스템 간 경로 벡터 프로토콜)와 혼동하지 않는 것이 중요하다.

📎 함께 암기하기
  • RIP: 홉 카운트 기반의 거리 벡터 라우팅 프로토콜
  • BGP: 자율 시스템(AS) 간 경로를 교환하는 외부 게이트웨이 프로토콜
  • IGP/EGP: 자율 시스템 내부용/외부용 라우팅 프로토콜 구분
  • 다익스트라 알고리즘: 최단 경로를 계산하는 그래프 알고리즘
  • ICMP: 네트워크 상태 진단 및 오류 메시지를 전달하는 프로토콜

TCP
OSI 7계층 중 전송 계층(4계층)에서 동작하며, 연결 지향적이고 신뢰성 있는 데이터 전송을 보장하는 프로토콜은 무엇인가?

TCP(Transmission Control Protocol)는 3-way handshake를 통해 연결을 설정하고, 순서 제어와 오류 검출 및 재전송을 통해 신뢰성 있는 데이터 전송을 보장한다. 이는 비연결형이며 신뢰성을 보장하지 않는 UDP와 대비된다.

VLSM (Variable Length Subnet Mask)
하나의 네트워크 대역을 필요에 따라 서로 다른 크기의 서브넷으로 나누어, IP 주소를 효율적으로 할당할 수 있도록 서브넷 마스크의 길이를 가변적으로 적용하는 서브네팅 기법을 가리키는 용어(약어)를 쓰시오.

VLSM은 하나의 네트워크를 여러 서브넷으로 나눌 때, 각 서브넷에 필요한 호스트 수에 맞춰 서로 다른 길이의 서브넷 마스크를 적용하는 기법입니다. 기존의 고정 길이 서브넷 마스킹(FLSM)은 모든 서브넷을 동일한 크기로 나누어 IP 주소 낭비가 발생하지만, VLSM은 필요한 만큼만 주소를 할당하여 주소 공간을 효율적으로 사용합니다. CIDR 표기법(예: /24, /27)과 함께 사용되며, 라우팅 프로토콜 중 RIPv1과 같이 클래스 기반 프로토콜은 VLSM을 지원하지 않고 OSPF, EIGRP, RIPv2 같은 클래스리스 프로토콜이 이를 지원한다는 점이 시험에서 자주 출제됩니다. 실기에서는 특정 서브넷 요구사항이 주어졌을 때 VLSM을 적용해 서브넷을 나누는 계산 문제와 함께 출제되는 경우가 많습니다.

📎 함께 암기하기
  • CIDR: 클래스 구분 없이 네트워크/호스트 비트를 자유롭게 나누는 주소 할당 방식
  • FLSM: 고정 길이로 동일한 크기의 서브넷만 생성하는 방식
  • NAT: 사설 IP와 공인 IP를 변환해주는 주소 변환 기술

정규화되지 않은 릴레이션에서 하나의 투플(행)을 삭제할 때, 삭제하려는 값과 관련 없는 다른 유용한 정보까지 함께 손실되는 현상을 무엇이라 하는가?

삭제 이상은 정규화가 되지 않은 테이블에서 특정 튜플을 삭제할 때 그 튜플에 포함된 다른 독립적인 정보까지 의도치 않게 함께 사라지는 문제를 말한다. 예를 들어 한 학생이 수강 중인 마지막 과목 정보를 삭제하면 그 학생의 학과 정보까지 테이블에서 사라지는 경우가 대표적이다. 이는 하나의 릴레이션에 여러 개념(학생, 과목, 수강)이 뒤섞여 있어 함수 종속이 복잡하게 얽혀 있기 때문에 발생하며, 정규화를 통해 릴레이션을 분해하면 해결할 수 있다. 이상 현상은 삽입 이상(새 데이터를 넣으려면 불필요한 정보까지 입력해야 함), 삭제 이상, 갱신 이상(중복된 데이터 중 일부만 수정되어 불일치가 발생) 세 가지로 나뉘며 실기에서는 세 유형을 구분하는 문제가 자주 출제된다. 정규형은 1NF(원자값), 2NF(부분 함수 종속 제거), 3NF(이행적 함수 종속 제거), BCNF(모든 결정자가 후보키)로 단계적으로 강화되며 각 단계는 특정 이상 현상을 제거하기 위해 도입된다.

제3정규형(3NF)4번 출제
릴레이션에서 기본키가 아닌 속성(비주요 속성)이 다른 비주요 속성에 종속되는 관계, 즉 이행적 함수 종속(transitive functional dependency)을 제거하여 만족시키는 정규형을 무엇이라 하는가?

제3정규형(3NF)은 릴레이션이 제2정규형(2NF)을 만족하면서 동시에 모든 비주요 속성이 기본키에 이행적으로 종속되지 않는 상태를 말합니다. 이행적 함수 종속이란 A→B, B→C가 성립할 때 A→C가 성립하는 관계로, 이를 제거하지 않으면 삽입/갱신/삭제 이상이 발생할 수 있습니다. 예를 들어 (학번, 학과, 학과사무실위치) 테이블에서 학번→학과, 학과→학과사무실위치가 성립하면 학번→학과사무실위치는 이행적 종속이므로 이를 분리해 별도 테이블로 만들어야 3NF를 만족합니다. 시험에서는 1NF(원자값), 2NF(부분함수종속 제거), 3NF(이행함수종속 제거), BCNF(모든 결정자가 후보키)의 단계별 차이와 각 단계에서 해결하는 이상현상의 종류를 구분하는 문제가 자주 출제되므로, 각 정규형이 어떤 종속성을 제거하는지 명확히 암기해야 합니다.

데이터베이스에서 참조하는 테이블의 기본키(또는 후보키)에 없는 값은 외래키 칼럼에 입력할 수 없도록 보장하여, 두 테이블 간의 참조 관계가 항상 일관되게 유지되도록 하는 무결성 제약조건의 이름을 쓰시오.

참조 무결성은 외래키(Foreign Key) 값이 반드시 참조되는 테이블의 기본키 값 중 하나와 일치하거나 NULL이어야 한다는 제약조건으로, 이를 통해 존재하지 않는 참조 대상을 가리키는 '고아 레코드'가 생기지 않도록 보장합니다. 이 제약조건이 위반되는 상황은 참조하는 테이블에 없는 값을 자식 테이블에 삽입하려 하거나, 부모 테이블의 레코드를 삭제했는데 이를 참조하는 자식 레코드가 남아있을 때 발생하며, 이를 방지하기 위해 CASCADE, SET NULL, RESTRICT 같은 참조 동작 옵션을 지정할 수 있습니다. 개체 무결성(Entity Integrity)이 기본키는 NULL이 될 수 없고 중복될 수 없다는 규칙인 것과 달리, 참조 무결성은 테이블 간의 관계를 다루는 제약조건이라는 점에서 구분해야 합니다. 정보처리기사 실기에서는 도메인 무결성, 개체 무결성, 참조 무결성을 구분하는 문제와 CASCADE/SET NULL 옵션의 동작 차이를 묻는 문제가 함께 출제되는 경향이 있습니다.

패킷(Packet)
OSI 7계층 중 네트워크 계층(3계층)에서 라우터가 IP 주소를 기반으로 경로를 설정하고 전달하는 데이터 전송 단위(PDU)를 무엇이라 하는가?

OSI 7계층과 TCP/IP 계층은 계층마다 데이터 전송 단위(PDU)가 다르며, 물리 계층은 비트(Bit), 데이터 링크 계층은 프레임(Frame), 네트워크 계층은 패킷(Packet), 전송 계층은 세그먼트(Segment, TCP) 또는 데이터그램(Datagram, UDP)이라 부른다. 네트워크 계층은 IP 주소를 이용한 논리적 주소 지정과 라우팅을 담당하며, 라우터가 이 계층에서 동작하여 패킷 단위로 최적 경로를 결정해 전달한다. 실기에서는 각 계층의 대표 장비(물리-리피터/허브, 데이터링크-스위치/브리지, 네트워크-라우터, 전송 이상-게이트웨이)와 PDU 명칭을 짝지어 묻는 문제가 자주 나오므로 계층별 PDU와 장비를 함께 암기해야 한다. 또한 TCP/IP 4계층 모델에서는 OSI의 물리+데이터링크 계층이 네트워크 액세스 계층으로 통합된다는 점도 자주 비교되는 포인트이다.

객체를 생성하는 인터페이스는 상위 클래스에 정의하되, 실제로 어떤 클래스의 인스턴스를 생성할지는 서브클래스가 결정하도록 하여 객체 생성 로직을 캡슐화하는 GoF 생성 패턴의 이름은 무엇인가?

팩토리 메서드 패턴은 객체 생성을 위한 메서드를 추상화하여 상위 클래스에서는 생성할 객체의 타입을 지정하지 않고, 서브클래스가 어떤 구체 클래스를 인스턴스화할지 결정하도록 위임하는 생성 패턴이다. 이를 통해 클라이언트 코드는 구체 클래스에 직접 의존하지 않고 인터페이스나 추상 클래스에만 의존하게 되어 결합도가 낮아지고 확장성이 높아진다. 유사한 추상 팩토리(Abstract Factory) 패턴과 자주 혼동되는데, 추상 팩토리는 서로 관련된 여러 객체군을 생성하는 인터페이스를 제공하는 반면 팩토리 메서드는 하나의 제품을 생성하는 메서드 자체를 서브클래싱으로 다형화한다는 점이 다르다. 정보처리기사 실기에서는 생성 패턴(싱글턴, 팩토리 메서드, 추상 팩토리, 빌더, 프로토타입) 간의 목적 차이를 구분하는 문제가 자주 출제되므로 각 패턴의 핵심 의도를 정확히 암기해야 한다.

형상 통제(변경 통제)/CCB(형상 통제 위원회)
소프트웨어 형상 관리(Configuration Management)에서, 식별된 형상 항목(Configuration Item)의 기준선(baseline)을 설정한 이후 발생하는 모든 변경 요청을 검토하고 승인 여부를 결정하는 통제 활동 또는 그 활동을 수행하는 위원회를 지칭하는 용어를 쓰시오.

형상 통제(Configuration Control)는 소프트웨어 형상 관리의 핵심 절차 중 하나로, 기준선이 설정된 이후 발생하는 변경 요청(Change Request)을 접수하여 그 영향도를 분석하고 승인, 보류, 거부 여부를 결정하는 활동이다. 이 활동을 수행하는 조직을 CCB(Configuration Control Board, 형상 통제 위원회)라고 부르며 실기 시험에서는 두 용어가 함께 출제되는 경우가 많다. 형상 관리는 식별, 통제, 상태 기록(감사), 형상 감사의 네 가지 주요 활동으로 구성되는데 그중 통제 단계가 변경 승인과 직접 관련된다. 기준선(baseline)은 공식적으로 검토되고 합의되어 이후 변경 시 공식 절차를 거쳐야 하는 형상 항목의 집합을 의미하므로 형상 통제와 짝을 이루는 개념이다. 헷갈리기 쉬운 점은 '형상 감사(Configuration Audit)'로, 이는 변경이 올바르게 반영되었는지 사후 검증하는 활동이라 통제와는 시점과 목적이 다르다.

화이트박스 테스트
프로그램의 내부 논리 구조(제어 흐름, 조건문, 반복문 등)를 분석하여 모든 코드 경로나 분기를 커버하도록 테스트 케이스를 설계하는 테스트 기법을 무엇이라 하는가? (대표적으로 기초 경로 검사(Basis Path Testing)를 포함하는 이 기법의 명칭을 쓰시오)

화이트박스 테스트는 프로그램의 내부 소스 코드, 로직, 구조를 직접 보면서 테스트 케이스를 설계하는 방법으로, 제어 흐름 그래프를 기반으로 한 기초 경로 검사(Basis Path Testing), 조건 검사(Condition Testing), 루프 검사(Loop Testing), 데이터 흐름 검사 등이 대표적인 기법입니다. 이는 내부 구조를 모르는 상태에서 입력과 출력만으로 테스트하는 블랙박스 테스트와 대비되는 개념으로, 시험에서는 두 기법의 차이와 각 기법에 속하는 세부 기술(동치 분할, 경계값 분석은 블랙박스 / 기초경로검사는 화이트박스)을 구분하는 문제가 자주 출제됩니다. 화이트박스 테스트의 목적은 모든 독립적인 경로가 최소 한 번은 실행되도록 보장하는 것이며, 커버리지 기준(문장 커버리지, 분기 커버리지, 조건 커버리지 등)으로 테스트의 충분성을 측정합니다.
