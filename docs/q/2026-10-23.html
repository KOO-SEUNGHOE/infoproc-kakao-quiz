2026-10-23 실기 문제

Q1

용어 단답

소프트웨어 요구사항 명세 기법 중, 수학적 기호와 표기법을 이용하여 요구사항을 정확하고 모호하지 않게 표현하며, Z 명세, VDM 등이 대표적인 예시로 사용되는 명세 기법을 무엇이라 하는가?

정답 보기 
정형 명세 (Formal Specification)

정형 명세는 수학적 기법(집합론, 논리학 등)을 바탕으로 요구사항을 엄밀하고 모호함 없이 기술하는 방법으로, 대표적으로 Z 명세, VDM(Vienna Development Method), Petri Net 등이 있습니다. 이는 자연어로 작성되는 비정형 명세와 대비되며, 검증 가능성이 높지만 작성과 이해에 전문 지식이 필요하다는 단점이 있습니다. 실기 시험에서는 정형 명세와 비정형 명세의 차이, 그리고 정형 명세 기법의 대표 예시(Z, VDM)를 묻는 문제가 자주 출제됩니다. 비정형 명세 기법으로는 자연어 기반의 유스케이스(Use Case)나 사용자 스토리 등이 있어 함께 비교해 암기해야 합니다.

📎 함께 암기하기
  • 비정형 명세: 자연어 기반으로 작성되어 이해하기 쉽지만 모호성이 존재함
  • Z 명세: 집합론과 술어논리 기반의 정형 명세 언어
  • VDM: 정형 명세를 위한 또 다른 수학적 모델 기반 기법
  • 유스케이스: 사용자와 시스템 간 상호작용을 시나리오로 기술하는 비정형 기법
  • UML: 요구사항 및 설계를 시각적으로 표현하는 준정형 모델링 언어
⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.

Q2

용어 단답

객체 생성 시 생성자를 직접 호출하지 않고, 서브클래스에서 어떤 클래스의 인스턴스를 생성할지 결정하도록 캡슐화하는 생성 패턴으로, 상위 클래스에서는 객체 생성을 위한 인터페이스만 정의하고 실제 객체 생성은 서브클래스에게 위임하는 디자인 패턴은 무엇인가?

정답 보기 
팩토리 메소드 패턴 (Factory Method Pattern)

팩토리 메소드 패턴은 GoF 디자인 패턴 중 생성 패턴에 속하며, 객체 생성 로직을 서브클래스로 위임하여 상위 클래스는 어떤 구체 클래스가 생성될지 알 필요 없이 인터페이스만 정의하는 방식입니다. 이를 통해 객체 생성 코드와 사용 코드를 분리하여 확장성과 유연성을 높일 수 있습니다. 실기에서는 팩토리 메소드 패턴과 추상 팩토리 패턴(Abstract Factory)의 차이를 묻는 문제가 자주 나오는데, 추상 팩토리는 관련된 여러 객체군을 생성하는 인터페이스를 제공하는 반면 팩토리 메소드는 하나의 제품 생성에 초점을 둡니다. 또한 싱글톤, 빌더 패턴 등 다른 생성 패턴과 함께 분류 체계(생성/구조/행위)를 암기하는 것이 중요합니다.

📎 함께 암기하기
  • 추상 팩토리 패턴: 서로 관련된 객체들의 군을 생성하는 인터페이스를 제공
  • 싱글톤 패턴: 클래스의 인스턴스를 하나만 생성하도록 보장
  • 빌더 패턴: 복잡한 객체의 생성 과정과 표현 방법을 분리
  • 전략 패턴: 알고리즘군을 정의하고 상호 교체 가능하게 캡슐화하는 행위 패턴
  • 옵저버 패턴: 객체 상태 변화를 다른 객체에 자동으로 통지하는 행위 패턴
⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.
