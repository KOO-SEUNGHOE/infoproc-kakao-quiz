2026-10-25 실기 문제

Q1

용어 단답

소프트웨어 화이트박스 테스트 기법 중, 프로그램 내 모든 분기문(if, switch 등)의 참(True)과 거짓(False) 결과가 각각 최소 한 번씩 실행되도록 테스트 케이스를 설계하는 커버리지 기법의 명칭을 쓰시오.

정답 보기 
분기 커버리지(Branch Coverage, 분기 테스트)

분기 커버리지는 화이트박스 테스트의 구조 기반 커버리지 기준 중 하나로, 프로그램 내 모든 조건문의 분기(참/거짓)가 적어도 한 번씩 실행되도록 테스트 케이스를 구성하는 기법이다. 이는 모든 실행 가능한 문장을 한 번씩 실행하기만 하면 되는 구문 커버리지(Statement Coverage)보다 강한 기준으로, 구문 커버리지를 만족해도 분기 커버리지를 만족하지 못할 수 있다는 점이 실기 시험에서 자주 출제되는 포인트다. 반면 조건 커버리지(Condition Coverage)는 각 개별 조건식의 참/거짓을 모두 검사하는 데 초점을 맞추지만 전체 분기의 참/거짓까지 보장하지는 않아 분기 커버리지와 구분된다. 두 조건을 모두 만족시키는 조건/분기 커버리지(Condition/Decision Coverage)와, 조건들의 모든 가능한 조합을 검사하는 다중 조건 커버리지(Multiple Condition Coverage)까지 함께 비교하여 암기해두는 것이 좋다.

📎 함께 암기하기
  • 구문 커버리지: 모든 실행 문장을 최소 한 번 실행
  • 조건 커버리지: 각 개별 조건식의 참/거짓을 모두 검사
  • 조건/분기 커버리지: 조건 커버리지와 분기 커버리지 기준을 동시에 만족
  • 다중 조건 커버리지: 조건들의 모든 가능한 논리적 조합을 검사
  • 블랙박스 테스트: 내부 구조를 보지 않고 입력과 출력만으로 테스트
⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.

Q2

용어 단답

관계형 데이터베이스에서 외래키(FOREIGN KEY) 값이 참조하는 릴레이션의 기본키 값으로 존재하거나 NULL이어야 한다는, 즉 존재하지 않는 값을 참조할 수 없도록 보장하는 무결성 제약조건의 명칭을 쓰시오.

정답 보기 
참조 무결성(Referential Integrity)

참조 무결성은 외래키 값이 반드시 참조 대상 테이블의 기본키 값 중 하나와 일치하거나 NULL이어야 한다는 제약조건으로, 두 테이블 간의 관계 일관성을 보장한다. 예를 들어 주문 테이블의 고객번호 외래키는 고객 테이블에 실제 존재하는 고객번호만 가질 수 있으며, 존재하지 않는 고객번호를 참조하면 참조 무결성이 깨진다. 이는 기본키 값이 NULL이 될 수 없고 중복될 수 없다는 개체 무결성(Entity Integrity)과 구분되는 개념으로, 실기에서 두 용어를 혼동하지 않도록 주의해야 한다. 참조 무결성 위반을 방지하기 위해 DBMS는 삭제/수정 시 CASCADE, SET NULL, RESTRICT 같은 참조 동작 옵션을 제공한다. 도메인 무결성(속성 값이 정의된 도메인 범위 내에 있어야 함)과 키 무결성(기본키의 유일성)까지 함께 정리해두면 무결성 제약조건 전체를 체계적으로 암기할 수 있다.

📎 함께 암기하기
  • 개체 무결성: 기본키는 NULL이 될 수 없고 중복되지 않아야 함
  • 도메인 무결성: 속성 값이 정의된 도메인(타입, 범위) 내에 있어야 함
  • 키 무결성: 하나의 릴레이션에 유일한 식별자가 존재해야 함
  • CASCADE: 참조되는 행 삭제/수정 시 참조하는 행도 함께 삭제/수정
  • SET NULL: 참조되는 행 삭제 시 외래키 값을 NULL로 설정
⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.
