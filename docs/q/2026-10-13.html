Q1

SQL 결과

다음 schema_sql을 실행한 후 query_sql을 수행했을 때의 결과를 예측하시오.

-- schema
CREATE TABLE department (
    dept_id INTEGER PRIMARY KEY,
    dept_name TEXT NOT NULL
);

CREATE TABLE employee (
    emp_id INTEGER PRIMARY KEY,
    emp_name TEXT NOT NULL,
    dept_id INTEGER,
    salary INTEGER,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
);

INSERT INTO department VALUES (1, '개발팀');
INSERT INTO department VALUES (2, '영업팀');
INSERT INTO department VALUES (3, '인사팀');

INSERT INTO employee VALUES (101, '김철수', 1, 5000);
INSERT INTO employee VALUES (102, '이영희', 1, 6500);
INSERT INTO employee VALUES (103, '박민수', 2, 4000);
INSERT INTO employee VALUES (104, '최지은', 2, 7000);
INSERT INTO employee VALUES (105, '정우성', 3, 3000);
INSERT INTO employee VALUES (106, '한소희', 1, 4500);
INSERT INTO employee VALUES (107, '오대리', 2, 5500);

-- query
SELECT e.emp_name, d.dept_name, e.salary
FROM employee e
JOIN department d ON e.dept_id = d.dept_id
WHERE e.salary > (
    SELECT AVG(salary)
    FROM employee
    WHERE dept_id = e.dept_id
)
ORDER BY e.dept_id, e.salary DESC;
정답 보기 
emp_name | dept_name | salary
이영희 | 개발팀 | 6500
최지은 | 영업팀 | 7000

이 쿼리는 상관 서브쿼리(correlated subquery)를 사용하여 각 직원의 급여가 자신이 속한 부서의 평균 급여보다 높은 경우만 선택합니다. 개발팀(dept_id=1)의 급여는 5000, 6500, 4500이고 평균은 (5000+6500+4500)/3=5333.33이므로 평균보다 높은 사람은 이영희(6500)만 해당됩니다. 영업팀(dept_id=2)의 급여는 4000, 7000, 5500이고 평균은 (4000+7000+5500)/3=5500이므로 평균보다 높은 사람은 최지은(7000)이며, 오대리(5500)는 평균과 같으므로 초과 조건(>)에 해당하지 않아 제외됩니다. 인사팀(dept_id=3)은 정우성 한 명뿐이라 평균이 자신의 급여와 같아 조건을 만족하지 않습니다. 따라서 최종 결과는 개발팀의 이영희, 영업팀의 최지은만 남고, dept_id와 salary 내림차순으로 정렬하면 이영희, 최지은 순서가 됩니다. 다시 확인하면 오대리는 평균과 같아 제외되므로 최종 결과는 이영희와 최지은 두 행만 출력됩니다.

Q2

용어 단답

하나의 네트워크 대역을 필요에 따라 서로 다른 크기의 서브넷으로 나누어, IP 주소를 효율적으로 할당할 수 있도록 서브넷 마스크의 길이를 가변적으로 적용하는 서브네팅 기법을 가리키는 용어(약어)를 쓰시오.

정답 보기 
VLSM (Variable Length Subnet Mask)

VLSM은 하나의 네트워크를 여러 서브넷으로 나눌 때, 각 서브넷에 필요한 호스트 수에 맞춰 서로 다른 길이의 서브넷 마스크를 적용하는 기법입니다. 기존의 고정 길이 서브넷 마스킹(FLSM)은 모든 서브넷을 동일한 크기로 나누어 IP 주소 낭비가 발생하지만, VLSM은 필요한 만큼만 주소를 할당하여 주소 공간을 효율적으로 사용합니다. CIDR 표기법(예: /24, /27)과 함께 사용되며, 라우팅 프로토콜 중 RIPv1과 같이 클래스 기반 프로토콜은 VLSM을 지원하지 않고 OSPF, EIGRP, RIPv2 같은 클래스리스 프로토콜이 이를 지원한다는 점이 시험에서 자주 출제됩니다. 실기에서는 특정 서브넷 요구사항이 주어졌을 때 VLSM을 적용해 서브넷을 나누는 계산 문제와 함께 출제되는 경우가 많습니다.

📎 함께 암기하기
  • CIDR: 클래스 구분 없이 네트워크/호스트 비트를 자유롭게 나누는 주소 할당 방식
  • FLSM: 고정 길이로 동일한 크기의 서브넷만 생성하는 방식
  • NAT: 사설 IP와 공인 IP를 변환해주는 주소 변환 기술
  • 서브넷 마스크: 네트워크 부분과 호스트 부분을 구분하는 32비트 값
  • 라우팅 프로토콜: OSPF, RIP 등 경로 정보를 교환하는 프로토콜
⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.

Q3

용어 단답

관계형 데이터베이스에서 외래키(FK) 값이 참조하는 테이블의 기본키(PK) 값과 일치하거나 NULL이어야 한다는, 즉 존재하지 않는 참조 값을 가질 수 없도록 보장하는 무결성 제약조건의 명칭을 쓰시오.

정답 보기 
참조 무결성 (Referential Integrity)

참조 무결성은 외래키 값이 참조 대상 테이블의 기본키 값 중 하나와 일치하거나, 또는 NULL이어야 한다는 제약으로, 두 테이블 간의 관계를 일관되게 유지하기 위한 핵심 규칙입니다. 이 제약이 깨지면 존재하지 않는 부모 레코드를 참조하는 '고아 레코드'가 생길 수 있으므로, DBMS는 INSERT/UPDATE/DELETE 시 이를 검사하여 위반 시 거부하거나 CASCADE, SET NULL 등의 참조 동작(referential action)을 수행합니다. 개체 무결성(Entity Integrity)이 기본키는 NULL이 될 수 없고 유일해야 한다는 제약인 것과 구분되며, 시험에서는 두 개념을 혼동하지 않는지 확인하는 문제가 자주 나옵니다. 또한 도메인 무결성(속성 값이 정의된 도메인 범위 내에 있어야 함)과 함께 관계형 DB의 3대 무결성 제약조건으로 묶여 출제됩니다.

📎 함께 암기하기
  • 개체 무결성: 기본키는 NULL이 될 수 없고 유일해야 함
  • 도메인 무결성: 속성 값이 정의된 데이터 타입과 범위를 만족해야 함
  • 외래키(FK): 다른 테이블의 기본키를 참조하는 속성
  • CASCADE: 참조 무결성 위반 시 연쇄적으로 삭제/수정하는 옵션
  • 사용자 정의 무결성: 비즈니스 규칙에 따라 사용자가 정의하는 제약조건
⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.
