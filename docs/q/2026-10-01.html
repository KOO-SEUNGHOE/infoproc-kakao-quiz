Q1

코드 출력 · Java

다음 Java 프로그램을 실행했을 때 출력되는 결과를 쓰시오.

public class Main {
    static int modify(int[] arr, int idx) {
        arr[idx] = arr[idx] * 2;
        return arr[idx] + idx;
    }

    public static void main(String[] args) {
        int[] numbers = {1, 2, 3, 4, 5};
        int sum = 0;

        for (int i = 0; i < numbers.length; i++) {
            sum += modify(numbers, i);
        }

        for (int i = 0; i < numbers.length; i++) {
            System.out.print(numbers[i] + " ");
        }
        System.out.println();
        System.out.println("sum=" + sum);
    }
}
정답 보기 
2 4 6 8 10 
sum=40

modify 메서드는 배열의 idx번째 값을 2배로 바꾸고 (바뀐 값 + idx)를 반환한다. 배열은 참조로 전달되므로 numbers 배열은 {2,4,6,8,10}으로 변경된다. sum은 (2+0)+(4+1)+(6+2)+(8+3)+(10+4) = 2+5+8+11+14 = 40이다.

Q2

코드 출력 · C

다음 C 프로그램을 실행했을 때 출력되는 결과를 쓰시오.

#include <stdio.h>

int calc(int *p, int n) {
    int result = 0;
    for (int i = 0; i < n; i++) {
        result += *(p + i);
        if (i % 2 == 0) {
            *(p + i) = *(p + i) + 10;
        }
    }
    return result;
}

int main() {
    int arr[5] = {1, 2, 3, 4, 5};
    int total = calc(arr, 5);

    for (int i = 0; i < 5; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");
    printf("total=%d\n", total);

    return 0;
}
정답 보기 
11 2 13 4 15 
total=15

calc 함수는 각 원소를 더해 result에 누적하면서(원본 값 1,2,3,4,5의 합 = 15), 인덱스가 짝수(0,2,4)인 원소에는 10을 더한다. 따라서 배열은 11,2,13,4,15로 바뀌고, total은 변경 전 값들의 합인 15가 반환된다.

Q3

SQL 결과

다음 schema_sql로 테이블을 생성하고 query_sql을 실행했을 때의 결과를 쓰시오.

-- schema
CREATE TABLE orders (
    order_id INTEGER PRIMARY KEY,
    customer VARCHAR(20),
    amount INTEGER
);

INSERT INTO orders VALUES (1, 'kim', 1000);
INSERT INTO orders VALUES (2, 'lee', 2000);
INSERT INTO orders VALUES (3, 'kim', 1500);
INSERT INTO orders VALUES (4, 'park', 3000);
INSERT INTO orders VALUES (5, 'lee', 500);
INSERT INTO orders VALUES (6, 'kim', 2500);
INSERT INTO orders VALUES (7, 'park', 1000);

-- query
SELECT customer, COUNT(*) AS cnt, SUM(amount) AS total
FROM orders
GROUP BY customer
HAVING SUM(amount) >= 3000
ORDER BY total DESC;
정답 보기 
customer | cnt | total
kim | 3 | 5000
park | 2 | 4000

customer별로 그룹화하여 합계를 구하면 kim=1000+1500+2500=5000(3건), lee=2000+500=2500(2건), park=3000+1000=4000(2건)이다. HAVING 조건(합계 3000 이상)을 만족하는 kim과 park만 남고, total 기준 내림차순 정렬하면 kim(5000), park(4000) 순서가 된다.

관계형 데이터베이스에서 테이블 내 속성들 간의 중복을 제거하고 삽입, 삭제, 갱신 시 발생할 수 있는 이상 현상(Anomaly)을 최소화하기 위해 테이블을 분해하는 과정을 무엇이라 하는가?

정답 보기 
정규화(Normalization)

정규화는 데이터 중복을 최소화하고 삽입/삭제/갱신 이상(Anomaly)을 방지하기 위해 릴레이션을 여러 개의 작은 릴레이션으로 분해하는 과정이다. 제1정규형부터 제5정규형(혹은 BCNF)까지 단계적으로 진행된다.
