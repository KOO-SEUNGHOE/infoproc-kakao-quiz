2026-10-24 실기 문제

Q1

용어 단답

UML 다이어그램 중 객체들 사이에 주고받는 메시지를 시간의 흐름에 따라 세로축(생명선)과 가로축(메시지 순서)으로 표현하여, 시스템의 동적인 상호작용 순서를 명확히 보여주는 다이어그램은 무엇인가?

정답 보기 
시퀀스 다이어그램(Sequence Diagram)

시퀀스 다이어그램은 UML의 대표적인 동적(행위) 다이어그램으로, 객체들을 가로로 배치하고 각 객체의 생명선(lifeline)을 세로로 그어 시간의 흐름에 따라 객체 간에 주고받는 메시지를 화살표로 표현한다. 활성화 막대(activation bar)를 통해 특정 시점에 어떤 객체가 실행 중인지도 나타낼 수 있다. 실기에서는 협력(커뮤니케이션) 다이어그램과 자주 비교되는데, 커뮤니케이션 다이어그램은 객체 간의 관계와 메시지 흐름을 강조하지만 시간 순서는 메시지에 번호를 매겨 표현하는 반면, 시퀀스 다이어그램은 생명선을 이용해 시간 순서를 시각적으로 명확히 드러낸다는 차이가 있다. 유스케이스 다이어그램이나 클래스 다이어그램 같은 정적 다이어그램과 혼동하지 않도록 주의해야 한다.

📎 함께 암기하기
  • 커뮤니케이션 다이어그램: 객체 간 관계와 메시지 흐름을 번호로 표현, 생명선 없음
  • 상태 다이어그램: 객체의 상태 변화와 전이를 표현
  • 액티비티 다이어그램: 업무 흐름이나 처리 로직의 순서를 표현
  • 유스케이스 다이어그램: 사용자와 시스템 기능 간의 관계를 표현하는 정적 다이어그램
  • 협력(Collaboration) 다이어그램: 객체 간 메시지 교환과 연관관계를 함께 표현
⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.

Q2

용어 단답

소프트웨어 요구사항 분석 기법 중, 사용자가 시스템을 어떻게 사용하는지를 액터와 시스템 간의 상호작용 흐름(기본 흐름과 대안/예외 흐름 포함)으로 단계별로 서술하는, 유스케이스를 구체화하는 명세 기법은 무엇인가?

정답 보기 
유스케이스 명세서(Use Case Specification, 유스케이스 기술서)

유스케이스 명세서는 유스케이스 다이어그램에서 도출된 각 유스케이스에 대해 액터, 사전조건, 사후조건, 기본 흐름(basic flow), 대안 흐름(alternative flow), 예외 흐름(exception flow)을 텍스트로 상세히 기술하는 요구사항 명세 기법이다. 유스케이스 다이어그램이 시스템 기능과 액터의 관계를 그림으로 간략히 보여주는 정적 표현이라면, 유스케이스 명세서는 그 유스케이스가 실제로 어떻게 동작하는지를 절차적으로 서술한 문서라는 점에서 차이가 있다. 실기에서는 요구사항 정의서, 유스케이스 다이어그램과 자주 비교 출제되므로 각각의 역할을 구분해서 암기해야 한다. 또한 애자일 방법론에서 사용하는 사용자 스토리(User Story)와도 비교되는데, 사용자 스토리는 간결한 한 문장 형태(As a ~, I want ~, so that ~)로 요구사항을 표현하는 반면 유스케이스 명세서는 훨씬 더 구조적이고 상세하다.

📎 함께 암기하기
  • 유스케이스 다이어그램: 액터와 시스템 기능 간의 관계를 도식화
  • 사용자 스토리: 애자일에서 간결한 문장으로 요구사항을 표현
  • 요구사항 정의서: 기능/비기능 요구사항을 체계적으로 정리한 문서
  • IEEE 830: 소프트웨어 요구사항 명세서(SRS) 작성 표준
  • 액티비티 다이어그램: 업무 처리 흐름을 순서도 형태로 표현
⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.
