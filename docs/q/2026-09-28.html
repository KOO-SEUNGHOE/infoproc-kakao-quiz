Q1

코드 출력 · Java

다음 Java 프로그램의 실행 결과를 예측하시오.

public class Main {
    static int modify(int[] arr, int idx) {
        arr[idx] = arr[idx] * 2;
        return arr[idx];
    }

    public static void main(String[] args) {
        int[] numbers = {1, 2, 3, 4, 5};
        int sum = 0;

        for (int i = 0; i < numbers.length; i++) {
            if (i % 2 == 0) {
                sum += modify(numbers, i);
            } else {
                sum += numbers[i];
            }
        }

        for (int n : numbers) {
            System.out.print(n + " ");
        }
        System.out.println();
        System.out.println("sum = " + sum);
    }
}
정답 보기 
2 2 6 4 10 
sum = 24

인덱스 0,2,4는 짝수이므로 modify가 호출되어 배열 값이 2배(1→2, 3→6, 5→10)로 바뀌고 그 반환값이 sum에 더해진다. 인덱스 1,3은 홀수이므로 원래 값 2,4가 그대로 더해진다. 최종 배열은 2 2 6 4 10이고 sum = 2+2+6+4+10 = 24이다.

Q2

코드 출력 · C

다음 C 프로그램의 실행 결과를 예측하시오.

#include <stdio.h>

int main(void) {
    int arr[5] = {10, 20, 30, 40, 50};
    int *p = arr;
    int total = 0;

    for (int i = 0; i < 5; i++) {
        if (i < 2) {
            *(p + i) = *(p + i) + 5;
        } else {
            *(p + i) = *(p + i) - 5;
        }
        total = total + *(p + i);
    }

    for (int i = 0; i < 5; i++) {
        printf("%d ", arr[i]);
    }
    printf("\ntotal = %d\n", total);

    return 0;
}
정답 보기 
15 25 25 35 45 
total = 145

i가 0,1일 때는 각 원소에 5를 더하여 10→15, 20→25가 되고, i가 2,3,4일 때는 5를 빼서 30→25, 40→35, 50→45가 된다. total은 이 변경된 값들의 누적 합으로 15+25+25+35+45 = 145이다.

Q3

SQL 결과

다음 테이블에 대해 주어진 SQL을 실행했을 때의 결과를 예측하시오.

-- schema
CREATE TABLE orders (
    order_id INTEGER PRIMARY KEY,
    customer TEXT,
    amount INTEGER
);

INSERT INTO orders VALUES (1, 'A', 1000);
INSERT INTO orders VALUES (2, 'B', 2000);
INSERT INTO orders VALUES (3, 'A', 1500);
INSERT INTO orders VALUES (4, 'C', 500);
INSERT INTO orders VALUES (5, 'B', 3000);
INSERT INTO orders VALUES (6, 'A', 2500);
INSERT INTO orders VALUES (7, 'C', 700);

-- query
SELECT customer, COUNT(*) AS cnt, SUM(amount) AS total
FROM orders
GROUP BY customer
HAVING SUM(amount) >= 3000
ORDER BY total DESC;
정답 보기 
customer | cnt | total
B | 2 | 5000
A | 3 | 5000

고객별로 그룹화하면 A는 1000+1500+2500=5000(3건), B는 2000+3000=5000(2건), C는 500+700=1200(2건)이다. HAVING 조건으로 합계가 3000 이상인 A와 B만 남고, total이 같으므로 order_id 순서상 먼저 삽입된 customer 순서(A, B)가 결과에 반영되지만 ORDER BY DESC에서 동점이면 원래 정렬 순서(내부 처리 순서, 보통 GROUP BY 결과 순서인 A, B)가 유지된다.

관계형 데이터베이스에서 이행적 함수 종속을 제거하여 얻어지는 정규화 단계의 이름을 쓰시오.

정답 보기 
제3정규형(3NF)

제2정규형을 만족하는 릴레이션에서 기본키가 아닌 속성이 다른 기본키가 아닌 속성에 종속되는 이행적 함수 종속을 제거하면 제3정규형이 된다. 이는 데이터 중복과 갱신 이상을 줄이기 위한 정규화 과정의 세 번째 단계이다.
