Q1

코드 출력 · Java

다음 Java 프로그램의 실행 결과를 예측하시오.

public class Main {
  static int modify(int[] arr, int idx) {
    arr[idx] = arr[idx] * 2;
    return arr[idx];
  }

  public static void main(String[] args) {
    int[] numbers = {1, 2, 3, 4, 5};
    int sum = 0;

    for (int i = 0; i < numbers.length; i++) {
      if (i % 2 == 0) {
        sum += modify(numbers, i);
      } else {
        sum += numbers[i];
      }
    }

    for (int i = 0; i < numbers.length; i++) {
      System.out.print(numbers[i] + " ");
    }
    System.out.println();
    System.out.println("sum = " + sum);
  }
}
정답 보기 
2 2 6 4 10 
sum = 24

인덱스가 짝수(0,2,4)일 때 modify 메서드가 배열 값을 2배로 바꾸고 그 값을 반환한다. numbers는 {1,2,3,4,5}에서 0,2,4번째 값이 2,6,10으로 바뀌어 최종 배열은 {2,2,6,4,10}이 된다. sum은 2(i=0)+2(i=1)+6(i=2)+4(i=3)+10(i=4) = 24이다.

Q2

코드 출력 · C

다음 C 프로그램의 실행 결과를 예측하시오.

#include <stdio.h>

void swap(int *a, int *b) {
  int temp = *a;
  *a = *b;
  *b = temp;
}

int calc(int *arr, int size) {
  int result = 0;
  for (int i = 0; i < size; i++) {
    result += arr[i];
    if (i > 0) {
      arr[i] = arr[i] + arr[i - 1];
    }
  }
  return result;
}

int main(void) {
  int nums[5] = {10, 20, 30, 40, 50};

  swap(&nums[0], &nums[4]);

  int total = calc(nums, 5);

  for (int i = 0; i < 5; i++) {
    printf("%d ", nums[i]);
  }
  printf("\n");
  printf("total = %d\n", total);

  return 0;
}
정답 보기 
50 70 100 140 150 
total = 150

swap으로 nums[0]과 nums[4]가 교환되어 배열은 {50,20,30,40,10}이 된다. calc 함수에서 result는 교환 직후의 원래 값들(50,20,30,40,10)의 합인 150으로 계산되고, 동시에 배열은 누적합 형태로 갱신되어 {50,70,100,140,150}이 되지만 마지막 원소는 result 계산 전 arr[4]=10과 arr[3]=140의 합인 150이 아니라 갱신 순서에 따라 160이 된다. 따라서 최종 배열은 {50,70,100,140,160}, total은 150이다.

SQL 결과

다음 schema_sql로 테이블을 생성하고 데이터를 삽입한 후, query_sql을 실행했을 때의 결과를 예측하시오.

-- schema
CREATE TABLE orders (
    order_id INTEGER PRIMARY KEY,
    customer VARCHAR(20),
    amount INTEGER
);

INSERT INTO orders VALUES (1, 'Kim', 10000);
INSERT INTO orders VALUES (2, 'Lee', 20000);
INSERT INTO orders VALUES (3, 'Kim', 15000);
INSERT INTO orders VALUES (4, 'Park', 5000);
INSERT INTO orders VALUES (5, 'Lee', 30000);
INSERT INTO orders VALUES (6, 'Park', 25000);
INSERT INTO orders VALUES (7, 'Kim', 5000);

-- query
SELECT customer, COUNT(*) AS cnt, SUM(amount) AS total
FROM orders
GROUP BY customer
HAVING SUM(amount) >= 30000
ORDER BY total DESC;
정답 보기 
customer | cnt | total
Lee | 2 | 50000
Park | 2 | 30000
Kim | 3 | 30000

customer별로 그룹화하여 합계를 구하면 Kim=30000(3건), Lee=50000(2건), Park=30000(2건)이다. HAVING 조건은 합계가 30000 이상인 그룹만 남기므로 Kim, Lee, Park 모두 해당되지만 ORDER BY total DESC로 정렬하면 Lee(50000), Park(30000), Kim(30000) 순이 되고 동률인 Park과 Kim은 입력 순서(그룹 생성 순서)에 따라 결정된다. SQLite 기본 정렬 안정성에 따라 Kim이 Park보다 먼저 나오는 경우가 일반적이므로 Lee, Kim, Park 순으로 출력된다.

용어 단답

릴레이션에서 기본키가 아닌 모든 속성이 기본키에 대해 이행적 함수 종속을 가지지 않도록 제거하는 정규화 단계는 제 몇 정규형인가?

정답 보기 
제3정규형(3NF)

제3정규형은 제2정규형을 만족하면서 기본키가 아닌 속성들이 기본키에 이행적 함수 종속(A→B, B→C이면 A→C)되지 않도록 분해하는 단계이다. 이를 통해 데이터 중복과 갱신 이상을 줄일 수 있다.
