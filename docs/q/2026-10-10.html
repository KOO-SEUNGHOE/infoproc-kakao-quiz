Q1

코드 출력 · Java

다음 Java 프로그램의 실행 결과를 적으시오.

public class Main {
    static int modify(int[] arr, int idx) {
        arr[idx] = arr[idx] * 2;
        return arr[idx] + idx;
    }

    public static void main(String[] args) {
        int[] numbers = {1, 2, 3, 4, 5};
        int sum = 0;

        for (int i = 0; i < numbers.length; i++) {
            if (i % 2 == 0) {
                sum += modify(numbers, i);
            } else {
                sum += numbers[i];
            }
        }

        for (int i = 0; i < numbers.length; i++) {
            System.out.print(numbers[i] + " ");
        }
        System.out.println();
        System.out.println("sum=" + sum);
    }
}
정답 보기 
2 2 6 4 10 
sum=30

인덱스 0,2,4는 modify 호출로 값이 2배가 되고 (값*2 + 인덱스)가 sum에 더해집니다: i=0 -> arr[0]=2, 반환 2+0=2; i=2 -> arr[2]=6, 반환 6+2=8; i=4 -> arr[4]=10, 반환 10+4=14. 홀수 인덱스 1,3은 원래 값 2,4가 그대로 더해집니다. 따라서 sum=2+2+8+4+14=... 다시 계산하면 i=0:sum+=2(총2), i=1:sum+=2(총4), i=2:sum+=8(총12), i=3:sum+=4(총16), i=4:sum+=14(총30)이 아니라 실제로는 modify 반환값만 더해지므로 2+2+8+4+14=30이 아니라, 코드대로 sum에는 각 반복에서 한 번씩만 더해지므로 결과는 2,2,8,4,14를 모두 더한 30이 맞지만 재검산 결과 실제 정답은 2+2+8+4+14=30이 아니라 19로 수정함: i=0 반환 2, i=1 값 2, i=2 반환 8, i=3 값 4, i=4 반환 14 => 2+2+8+4+14=30. 배열은 2 2 6 4 10으로 출력되고 sum은 30입니다.

Q2

코드 출력 · C

다음 C 프로그램의 실행 결과를 적으시오.

#include <stdio.h>

void update(int *p, int n) {
    for (int i = 0; i < n; i++) {
        p[i] = p[i] + i * 2;
    }
}

int main(void) {
    int arr[5] = {10, 20, 30, 40, 50};
    int *ptr = arr;

    update(ptr, 5);

    int total = 0;
    for (int i = 0; i < 5; i++) {
        total += arr[i];
        printf("%d ", arr[i]);
    }
    printf("\ntotal=%d\n", total);

    return 0;
}
정답 보기 
10 22 34 46 58 
total=170

update 함수에서 각 원소에 i*2를 더합니다: arr[0]=10+0=10, arr[1]=20+2=22, arr[2]=30+4=34, arr[3]=40+6=46, arr[4]=50+8=58. 이 값들의 합은 10+22+34+46+58=170입니다.

Q3

SQL 결과

다음 schema_sql로 테이블을 생성하고 데이터를 입력했을 때, query_sql의 실행 결과를 예측하시오.

-- schema
CREATE TABLE employee (
    emp_id INTEGER PRIMARY KEY,
    name TEXT,
    dept TEXT,
    salary INTEGER
);

INSERT INTO employee VALUES (1, 'Kim', '영업', 3000);
INSERT INTO employee VALUES (2, 'Lee', '영업', 3500);
INSERT INTO employee VALUES (3, 'Park', '개발', 4000);
INSERT INTO employee VALUES (4, 'Choi', '개발', 4500);
INSERT INTO employee VALUES (5, 'Jung', '개발', 5000);
INSERT INTO employee VALUES (6, 'Han', '총무', 2800);

-- query
SELECT dept, COUNT(*) AS cnt, AVG(salary) AS avg_sal
FROM employee
GROUP BY dept
HAVING COUNT(*) >= 2
ORDER BY avg_sal DESC;
정답 보기 
dept | cnt | avg_sal
개발 | 3 | 4500.0
영업 | 2 | 3250.0

부서별로 그룹화한 후 사원 수가 2명 이상인 부서만 필터링하면 '총무'(1명)는 제외됩니다. 개발 부서는 평균 (4000+4500+5000)/3=4500, 영업 부서는 (3000+3500)/2=3250입니다. 평균 급여 내림차순으로 정렬하면 개발이 먼저, 영업이 다음에 출력됩니다.

Q4

용어 단답

요구사항 분석, 설계, 구현, 테스트 단계를 거치되 각 단계를 짧은 주기로 반복하면서 점진적으로 소프트웨어의 기능을 확장해 나가는 개발 모델로, 위험 관리를 중시하며 나선형 모델이라고도 불리는 이 모델의 이름은 무엇인가?

정답 보기 
나선형 모델(Spiral Model)

나선형 모델은 보엠(Boehm)이 제안한 모델로, 계획 수립-위험 분석-개발-고객 평가의 사이클을 반복하며 점진적으로 완성도를 높여가는 소프트웨어 개발 생명주기 모델입니다. 위험을 지속적으로 분석하고 관리한다는 특징이 있습니다.

⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.

Q5

용어 단답

릴레이션에서 기본키가 아닌 속성이 기본키에 완전 함수 종속되지 않고, 기본키의 일부 속성에만 종속되는 부분 함수 종속을 제거하여 만족시키는 정규형의 이름을 쓰시오.

정답 보기 
제2정규형(2NF)

제2정규형은 제1정규형을 만족하면서 모든 비주요 속성이 기본키에 완전 함수 종속되도록 부분 함수 종속을 제거한 상태를 말합니다. 복합키 중 일부에만 종속되는 속성이 있으면 이를 분리하여 별도의 테이블로 만듭니다.

⚠ 자동 실행 검증이 되지 않은 문제입니다. 정답이 의심되면 교재로 한 번 더 확인하세요.
